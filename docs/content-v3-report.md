# Отчёт: ротация контента v3 (`feature/content-v3`)

База: `sirius_gate` @ `964b48e`. Ветка: `feature/content-v3`, коммит на каждый этап.

## Baseline (расхождение с ТЗ)

ТЗ ожидало 249 тестов с красным перф-смоуком zendo. Фактический baseline на
`964b48e`: **260 passed, 0 failed** — перф-смоук
`test_zendo_warm_generation_smoke_and_legacy_evaluator` на этой машине
проходил (2.6 s из бюджета 5 s). Этап P выполнен по ТЗ независимо от этого.
`npm run check` и `npm run build` — зелёные.

Итог ветки: **155 passed** на бэке, tsc/vite — зелёные.

## Что сделано

- **R — удаление.** chess960 (целиком), penultima v1+v2 (+ каталоги правил),
  nim_like (с мизером), geo_graph (только оно из atlas.py) удалены жёстко:
  бэкенд, фронтенд (экраны Chess960/Penultima/Counters), тесты. Доска
  `Chessboard` сохранена — её использует leaper_board (machine_reach).
  Валидация: контест с неизвестным/выведенным семейством → 422
  `TASK_FAMILY_UNKNOWN` с перечнем ключей; в *хранимых* конфигах незнакомые
  семейства по-прежнему тихо пропускаются (обратная совместимость).
  Телеметрия историчecких попыток с retired-семейством не падает: строка
  задачи помечается `family: X (retired)` (+ тест). Гео-веса дефолта
  geometry_world перераспределены: zendo 40 / transform 30 / probability 30.
  Grep-критерий чист; действие `move` (только penultima) удалено из схем.
- **P — перф.** `GraphFeatures` (lru_cache 65536): смежность, степени,
  связность, циклы, треугольники, двудольность, пересечения — один раз на
  граф; атомы читают бандл. `clear_rule_space_cache()` сбрасывает и его.
- **U — мультивселенная.** Golden-фикстура geo_zendo (100 кейсов) снята ДО
  правок ядра и держит `geometry-zendo-v2` байт-в-байт. Из ядра извлечён
  `core/zendo_engine.py`: протокол вселенной, `UniverseSpace` с кэшем по
  `(universe_version, dsl_version)`, generic select_material (минимальная
  пара, границы VS, near-miss экзамен, entropy-пробы), общий probe-transition
  с точным ΔH и общий скоринг. Фильтры вырожденности обязательны для каждой
  вселенной (дедуп по MDL, base rate 0.12–0.88, минимальная пара по
  построению). GraphUniverse — извлечение без изменения поведения.
  Новые семейства (все `*-v1`, интерактивные, события `zendo_probe`
  с `gain_bits_actual/best`):
  - `token_zendo` — 3–7 фишек (num 1..9 × RGB), 9 атомов спеки + XOR-гибриды
    из общих комбинаторов; 236 правил;
  - `point_zendo` — 5–8 точек на 12×12; атомы: 3 на прямой, выпуклое
    положение, центр симметрии, параллелограмм, 4 на окружности, различные
    расстояния. Сэмплер с целевым подмешиванием (метрики отбраковки в build
    log) — решёточная коллинеарность не режет base rate;
  - `grid_zendo` — узоры 5×5; атомы: 7 нетривиальных элементов D4,
    связность, чётности компонент/клеток/строк/столбцов, доминошки (точное
    паросочетание). Пробы свободной формы: участник рисует узор, ΔH
    считается вживую. Популяция 640 — на 5×5 всего ~82 C4-симметричных
    узора в границах заполнения, иначе литералы симметрии не проходят
    base-rate фильтр.
- **W — hidden_wiring.** GF(2)-матрица L×B (4–6 ламп, 4–5 кнопок), аккорды
  только парами (легенда в UI; design-note о тривиализации одиночных
  нажатий — в докстринге модуля). Варианты «совладай» (цель достижима по
  построению, кратчайший BFS-сертификат в private, автозавершение) и
  «пойми» (экзамен из 3 аккордов, исключённых из проб; разрешимость через
  ранг индикаторов). Точный ΔH: H = L·(B−1−rank). Бюджет 8, первая проба
  обучающая и бесплатная (митигация риска понятности). Идемпотентность по
  `client_action_id` (replay/`reused`-конфликт).
- **S — пространственные.** `fold_punch`: 2–3 сгиба пополам, диагональ на
  сложности 4–5, 1–2 дырки; генератор — прямая стековая модель, чекер —
  развороты (диагональ — транспонирование), в тестах сверены поклеточным
  перебором; скоринг: точное множество + Jaccard в `continuous_score`.
  `spatial_bank`: rotation-match (полимино 6–9 клеток **без нетривиальных
  симметрий** — фильтр проверен перечислением 8 изометрий; дистракторы: два
  отражения + близкая фигура) и assembly (ровно одна пара частей собирает
  цель — перебор изометрий/положений в генераторе и в тестах).
- **C — динамический слой.** Мягкая квота ≥3 показа на семейство
  (`min_family_exposures` поверх weighted coverage; api включает при
  достаточном остатке времени — 90 с на недостающий показ). `learning_slope`
  per family в экспорте телеметрии (OLS по номеру встречи; null при <2
  точках; вне скоринга сезона 1). `/hint`: категория правила из
  фиксированного словаря, множитель 0.7 к `continuous_score`, повторный
  недоступен, событие `prompt_used`.
- **Дефолт-конфиг** конструктора — веса §7: geo_zendo 14, token 12,
  point 12, grid 12, wiring 14, machine_reach 12, fold 8, spatial 6,
  dice 6, transform 2, probability 2.
- **Смоук через фронт**: контест с дефолт-конфигом, попытка в браузере —
  по одной задаче каждого из 11 семейств (все верно; token_zendo 0.7 из-за
  проверенного /hint; wiring — кликами/аккордом, grid — рисованной пробой).
  Плюс автоматический e2e-смоук `test_default_contest_smoke.py`.

## Замеры производительности (100 тёплых генераций)

| Семейство | Время |
|---|---|
| geo_zendo v2 | 2.6 s → **1.05 s** после P (бюджет 5 s) |
| token_zendo | 0.03 s (сборка пространства 0.03 s) |
| point_zendo | 2.3 s (сборка 0.35 s) |
| grid_zendo | 0.54 s (сборка 0.09 s) |
| hidden_wiring | ~0.004 s (1000 генераций + валидация 0.04 s) |
| fold_punch | <0.01 s |
| spatial_bank | 0.05 s (было 33 s до кэша изометрий) |

Сборки пространств правил кэшируются на процесс; кэш атомных значений в
движке (semantics-preserving) дал основной выигрыш point_zendo.

## Отложено / решения по ходу (код первичен)

- **Этапы X (balance_oracle, liar_oracle) и T (translation) не реализованы**
  — по ТЗ допускаются после приёмки A–C отдельным решением.
- Протокол вселенной адаптирован под фактическое ядро: фиксированная
  детерминированная популяция + перечисление всех одношаговых мутаций
  (вместо `sample`/`mutate` одиночных из эскиза ТЗ) — это то, как работает
  существующий движок, и что требуется для воспроизводимости.
- Для замороженного `geometry-zendo-v2` категория /hint выводится из
  `rule_index` на лету (private зафиксирован golden-фикстурой байт-в-байт);
  у новых семейств категория записана в private при генерации, как в ТЗ.
- «Достаточный остаток времени» для квоты режиссёра формализован как
  90 с × число недостающих показов; версия режиссёра не бампалась — квота
  оперативный сигнал (как ремедиация), вне версионируемой идентичности
  маршрута.
- INTERACTIVE_TASK_REQUIRES_MOVE и связанная батарея умерли вместе с
  penultima: семейств, завершаемых только ходами, не осталось; батарея
  идемпотентности перенесена на hidden_wiring.
- Grep-критерий R.4: имена retired-семейств не встречаются в
  `backend/app` и `src/` (валидация неизвестных семейств сделана без
  хранения их имён); истории в тестах/доках — вне критерия.
