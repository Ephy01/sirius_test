# Sirius Gate

Рабочий вертикальный срез платформы интеллектуальных отборов Сириуса.
Реализована серверная цепочка:

`контест → участник → персональный код → попытка → задача → журнал событий`.

Организатор собирает смешанный контест из семейств, назначает им визуальные
скины, веса и границы сложности, добавляет участников, выпускает коды и
публикует контест. Участник входит по выданному коду, отдельной кнопкой
запускает серверную попытку и работает в двухзонной среде: задача слева,
чат-команды справа. Понятие «мир» сохранено только для отображения старых
контестов; единица маршрутизации новых контестов — семейство.

Новый смешанный контест содержит десять ротационных семейств и одну
скриптовую математическую задачу. В шахматном семействе участник выбирает
фигуры на предложенных клетках и должен покрыть все цели с минимальной
суммарной стоимостью. Генератор строит вариант воспроизводимо и точным
перебором проверяет, что оптимальная расстановка существует и единственна.
Старые Chess960 и Dice & Chess остаются доступными для уже сохранённых задач.

В Penultima участник управляет переименованной фигурой через чат и должен
доставить её к маяку. Правило движения генерируется из версионированного
пространства симметричных векторов, остаётся скрытым и сохраняется на
протяжении трёх целей. Каждый ход
получает вердикт арбитра; допустимый ход меняет доску, а недопустимый оставляет
позицию прежней. Следующая цель начинается из фактической финальной позиции и
выбирает ветвь `advance`, `consolidate` или `remediate` по истории прохождения.

Геометрические семейства используют единый визуальный язык точек, рёбер и фигур.
В нём есть четыре процедурных семейства: геометрический Zendo со скрытым
правилом и ограниченными пробами (30%), преобразования и инварианты (25%),
комбинаторика и точные вероятности на графах (25%), графовые конструкции
(20%). Ответы проверяются формально: Zendo — по скрытому предикату,
преобразования — по группе симметрий квадрата, вероятности — полным перебором
исходов, конструкции — по свойствам получившегося графа.

Семейство `machine_reach` создаёт четыре вида конечных машин: лампы над
GF(2), аффинные числовые операции, перестановки карточек и прыгуна на доске.
Участник применяет операции пошагово и завершает задачу ответом `done` или
`impossible`. Достижимость проверяется точным солвером; недостижимость всегда
имеет формальный сертификат инварианта. `nim_like` предлагает один решающий ход
в normal- или misère-игре с кучами и проверяется точной таблицей состояний.

Новые контесты используют единый `director-v2`. Сначала режиссёр проводит
участника через короткую калибровку по выбранным семействам. Глава Penultima не
прерывается до третьей цели. После ошибки один раз выдаётся связанная
восстановительная задача того же семейства, после повторной неудачи маршрут
переключается, чтобы участник не застревал. В дальнейшем семейства чередуются по
их весам и дефициту показов. Для каждого семейства отдельно учитываются три
последних результата: два положительных свидетельства повышают уровень, два
отрицательных понижают его. Участнику показывается только нейтральная стадия
маршрута, но не внутренняя оценка.

Задачи воспроизводимо создаются из закрытого seed попытки, номера задачи,
контекста, решения режиссёра и версии генератора. Конфигурация траектории
фиксируется при запуске попытки. Проверку выполняет серверный код, а участник
получает только публичное состояние и нейтральную обратную связь. В append-only
журнал попадают запуск попытки, генерация, решения маршрута, ответы, пошаговые
взаимодействия, оценивание, пропуск и истечение времени. Интерфейс дополняет
этот журнал событиями, которые сервер сам увидеть не может: фактическим показом
задачи, отправкой команды, копированием и вставкой текста, уходом со вкладки и
возвращением. Клиентские события уходят через последовательную очередь с
повторной отправкой при временной ошибке.
Для каждого события сохраняются серверное время, клиентская отметка времени и
порядковый номер внутри сессии браузера.

Если в конфигурации указан `cohort_seed`, участники одной волны получают
одинаковые воспроизводимые варианты на одинаковых шагах. Скин в вычислении seed
не участвует. Каждое событие оценивания содержит непрерывный балл, сложность,
семейство и версию генератора.

Команды участника:

- `/help` — справка;
- `/answer <текст>` — зафиксировать ответ и автоматически открыть следующую задачу;
- `/move c2 d3` — предложить ход арбитру в Penultima;
- `/test <код>` — проверить доступную карточку в геометрическом Zendo;
- `/op <id>` — применить операцию в задаче `machine_reach`;
- `/undo` — отменить последнюю операцию машины;
- `/reset` — вернуть интерактивную задачу в исходное состояние;
- `done` / `impossible` — завершить машину или заявить недостижимость;
- `take <куча> <число>` / `проигрышная` — ответить в `nim_like`;
- `/history` — показать последние пробы текущей главы Penultima;
- `/skip` — пропустить и автоматически открыть следующую задачу;
- `/next` — повторить переход, если автоматическая загрузка прервалась.

Если ответ уже сохранён, но загрузка следующего уровня прервалась, интерфейс
сообщает об этом отдельно: повторная отправка ответа не нужна.

## Запуск

Сначала API:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
.venv/bin/uvicorn app.main:app --reload --port 8001
```

Затем frontend из корня репозитория:

```bash
npm install
npm run dev
```

Vite запустит приложение на `http://127.0.0.1:4173` и проксирует `/api` в
FastAPI на порту `8001`.

## Production deployment

Для production используется стек `Caddy + FastAPI + PostgreSQL`. После
создания `.env.production` первый запуск выполняется через
`./deploy/deploy.sh`, последующие обновления — через `./deploy/update.sh`,
резервное копирование — через `./deploy/backup.sh`, откат — через
`./deploy/rollback.sh`.

## Локальный доступ

- код организатора: `ORBIT-ADMIN`;
- коды участников создаются внутри конструктора контеста.

В браузере хранится только подписанная серверная сессия и маска кода. Открытые
коды участников возвращаются один раз при генерации; в базе сохраняется
HMAC-SHA256.

### Повторная проверка участника

Войдите как организатор, откройте нужный контест и нажмите
«Управлять доступом». Панель отдельно показывает состояние персонального кода
и состояние последней часовой попытки:

- «Перевыпустить код» немедленно отзывает старый код и один раз показывает
  новый;
- «Разрешить новую попытку» выдаёт одноразовое право на повторный запуск;
- «Скачать лог» формирует UTF-8 `.txt` со всеми попытками участника, задачами,
  событиями и интервалами времени;
- таймер новой попытки начинается только после того, как участник снова войдёт
  по действующему коду и нажмёт «Начать попытку».

Канонический журнал хранится в базе. Текстовый файл строится только в момент
скачивания, поэтому одновременные действия не могут повредить файл, а
предыдущие попытки, задачи и события сохраняются.

Неотправленные браузерные события временно сохраняются в пределах вкладки и
повторно отправляются с теми же идентификаторами. После дедлайна сервер ещё
пять минут принимает только подтверждённые клиентским временем события этой
попытки; выполнять игровые команды или отвечать на задачи в это окно нельзя.

События вкладки и буфера обмена являются клиентской телеметрией: они полезны
для последующего анализа, но сами по себе не доказывают использование внешнего
ИИ. Серверные ответы, ходы, пропуски и результаты проверки остаются
каноническими независимо от браузерной телеметрии.
