# Sirius Gate

Рабочий вертикальный срез платформы интеллектуальных отборов Сириуса.
Реализована серверная цепочка:

`контест → участник → персональный код → попытка → задача → журнал событий`.

Организатор выбирает «Шахматный» или «Геометрический» мир, настраивает
семейства, добавляет участников, выпускает коды и публикует контест. Участник
входит по выданному коду, отдельной кнопкой запускает серверную попытку и
работает в двухзонной среде: задача слева, чат-команды справа.

В текущем срезе подключены три формально проверяемых семейства. Chess960
начинается с проверки расстановки, затем предлагает исправить её одной
перестановкой и посчитать все допустимые исправления. В Dice & Chess на каждом
уровне присутствует доска: сначала участник считает вероятность по типам фигур
на всей доске или в указанной области, затем бросок связывается с легальной
шахматной позицией, ходами, взятиями и шахами. Точная вероятность вычисляется
сервером перебором конечного пространства исходов.

В Penultima участник управляет переименованной фигурой через чат и должен
доставить её к маяку. Правило движения выбирается из версионированного
каталога, остаётся скрытым и сохраняется на протяжении трёх целей. Каждый ход
получает вердикт арбитра; допустимый ход меняет доску, а недопустимый оставляет
позицию прежней. Следующая цель начинается из фактической финальной позиции и
выбирает ветвь `advance`, `consolidate` или `remediate` по истории прохождения.

«Геометрический мир» использует единый визуальный язык точек, рёбер и фигур.
В нём есть четыре процедурных семейства: геометрический Zendo со скрытым
правилом и ограниченными пробами (30%), преобразования и инварианты (25%),
комбинаторика и точные вероятности на графах (25%), графовые конструкции
(20%). Ответы проверяются формально: Zendo — по скрытому предикату,
преобразования — по группе симметрий квадрата, вероятности — полным перебором
исходов, конструкции — по свойствам получившегося графа.

Новые контесты используют `chess-world-director-v1` или
`geometry-world-director-v1`. Сначала режиссёр проводит
участника через короткую калибровку по выбранным семействам. Глава Penultima не
прерывается до третьей цели. После ошибки один раз выдаётся связанная
восстановительная задача того же семейства, после повторной неудачи маршрут
переключается, чтобы участник не застревал. В дальнейшем семейства чередуются по
их весам и дефициту показов. Для каждого семейства отдельно учитываются три
последних результата: два положительных свидетельства повышают уровень, два
отрицательных понижают его. Участнику показывается только нейтральная стадия
маршрута, но не внутренняя оценка.

Задачи воспроизводимо создаются из закрытого seed попытки, номера задачи,
контекста, решения режиссёра и версии генератора. Конфигурация траектории
фиксируется при запуске попытки. Проверку выполняет серверный код, а участник
получает только публичное состояние и нейтральную обратную связь. В append-only
журнал попадают запуск попытки, генерация, решения маршрута, ответы, пошаговые
взаимодействия, оценивание, пропуск и истечение времени.

Команды участника:

- `/help` — справка;
- `/answer <текст>` — зафиксировать ответ и автоматически открыть следующую задачу;
- `/move c2 d3` — предложить ход арбитру в Penultima;
- `/test <код>` — проверить доступную карточку в геометрическом Zendo;
- `/history` — показать последние пробы текущей главы Penultima;
- `/skip` — пропустить и автоматически открыть следующую задачу;
- `/next` — повторить переход, если автоматическая загрузка прервалась.

Если ответ уже сохранён, но загрузка следующего уровня прервалась, интерфейс
сообщает об этом отдельно: повторная отправка ответа не нужна.

## Запуск

Сначала API:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
.venv/bin/uvicorn app.main:app --reload --port 8001
```

Затем frontend из корня репозитория:

```bash
npm install
npm run dev
```

Vite запустит приложение на `http://127.0.0.1:4173` и проксирует `/api` в
FastAPI на порту `8001`.

## Локальный доступ

- код организатора: `ORBIT-ADMIN`;
- коды участников создаются внутри конструктора контеста.

В браузере хранится только подписанная серверная сессия и маска кода. Открытые
коды участников возвращаются один раз при генерации; в базе сохраняется
HMAC-SHA256.

### Повторная проверка участника

Войдите как организатор, откройте нужный контест и нажмите
«Управлять доступом». Панель отдельно показывает состояние персонального кода
и состояние последней часовой попытки:

- «Перевыпустить код» немедленно отзывает старый код и один раз показывает
  новый;
- «Разрешить новую попытку» выдаёт одноразовое право на повторный запуск;
- таймер новой попытки начинается только после того, как участник снова войдёт
  по действующему коду и нажмёт «Начать попытку».

Предыдущие попытки, задачи и события при этом сохраняются.

