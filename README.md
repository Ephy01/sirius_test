# Sirius Gate

Веб-платформа, на которой участник решает процедурно сгенерированные
математические задачи, может обращаться к встроенному ИИ-ассистенту, а сервер
записывает хронологию его действий.

Цепочка работы: `контест → участник → персональный код → попытка → задача → журнал событий`.

- Организатор собирает контест из семейств задач, задаёт веса и границы
  сложности, добавляет участников, выпускает персональные коды и публикует
  контест.
- Участник входит по коду, запускает ограниченную по времени попытку и работает
  в двух зонах: слева условие и интерактивная сцена, справа чат с командами и
  ассистентом.
- Сервер генерирует задачи воспроизводимо, сам проверяет ответы, подбирает
  следующую задачу по истории участника и пишет каждое действие в журнал.
- Организатор скачивает журнал участника для анализа.

Полное описание находится в [docs/DOCUMENTATION.md](docs/DOCUMENTATION.md).

## Структура

```text
backend/app/
  api/              маршруты REST, по файлу на раздел API
  tasks/            семейства задач, реестр и director
  ai/               ассистент: контекст, промпты, провайдер, лимиты
  routing.py        выбор следующей задачи и её seed
  task_flow.py      создание, оценка и закрытие задачи
  events.py         журнал событий попытки
  telemetry.py      текстовый экспорт журнала
backend/tests/      pytest
src/                клиент на React и TypeScript
  api/              HTTP-клиент и разбор ответов
  tasks/            по модулю на вид задачи: состояние, парсер, сцена, команды, тексты
  participant/      рабочее место участника, команды чата, телеметрия
  organizer/        конструктор контеста и панель доступа
deploy/             Caddy и сценарии эксплуатации
docs/               документация
```

## Запуск

API:

```bash
cd backend
python3 -m venv .venv
.venv/bin/pip install -e '.[test,dev]'
cp .env.example .env
.venv/bin/uvicorn app.main:app --reload --port 8001
```

Клиент, из корня репозитория во втором терминале:

```bash
npm ci
npm run dev
```

Vite открывает приложение на `http://127.0.0.1:4173` и проксирует `/api` на
порт `8001`. Код организатора для локального запуска задаётся переменной
`ORGANIZER_CODE` в `backend/.env`, в примере это `ORBIT-ADMIN`. Коды участников
выпускаются в конструкторе контеста. Описание API доступно на
`http://127.0.0.1:8001/docs`.

## Семейства задач

| Ключ | Что делает участник |
|---|---|
| `geo_zendo`, `token_zendo`, `point_zendo`, `grid_zendo` | по примерам и пробам выясняет скрытое правило и классифицирует контрольные объекты |
| `hidden_wiring` | экспериментами восстанавливает скрытую проводку ламп |
| `machine_reach` | переводит конечную систему в заданное состояние или заявляет недостижимость |
| `chess_coverage` | покрывает цели фигурами с минимальной стоимостью |
| `fold_punch` | отмечает дырки на развёрнутом листе |
| `geo_transform`, `geo_probability` | распознаёт преобразование фигуры, считает вероятность на графе |
| `dice_chess` | считает вероятность события на доске с кубиком фигур |
| `classic_math` | даёт развёрнутый ответ на одну из двух классических задач |

Каждое семейство — один модуль в `backend/app/tasks/` с записью `FAMILY`.
Как добавить новое семейство, описано в
[разделе 23 документации](docs/DOCUMENTATION.md#23-как-добавить-новое-семейство-задач).

## Точки расширения

- **Новые типы задач как модули.** Файл на Python в папке `TASK_MODULES_DIR`
  подключается без правки платформы: он использует пакет `sirius_gate` и
  собирает сцену из готовых блоков, поэтому код на клиенте не нужен. Примеры и
  инструкция лежат в отдельном репозитории
  [sirius_gate_modules](https://github.com/Ephy01/sirius_gate_modules), устройство
  описано в разделе 23.7 документации.
- **Новые типы задач внутри платформы.** На сервере контракт `TaskFamily` в
  `backend/app/tasks/family.py` и список модулей в
  `backend/app/tasks/registry.py`. На клиенте запись `TaskKind` в
  `src/tasks/<kind>.tsx` и строка в `src/tasks/registry.ts`.
- **Другая языковая модель.** Протокол `AssistantProvider` в
  `backend/app/ai/provider.py`, выбор провайдера в `provider_from_settings`.
  Подробности в разделе 15 документации.
- **Анализ телеметрии.** Перечень событий и их полей приведён в разделе 16
  документации. Машинно-читаемой выгрузки пока нет, данные лежат в таблицах
  `attempt_events`, `task_instances`, `task_interactions` и `ai_turns`.

## Ветки

- `main` — стабильная версия, из неё выполняется развёртывание.
- `dev` — текущая разработка. Изменения попадают в `main` через pull request
  после прохождения CI.

Версия генератора (`GENERATOR_VERSION`) фиксирует смысл уже выданных задач.
Любое изменение генерации или проверки требует новой версии.

## Развёртывание

Production-стек: Caddy, FastAPI и PostgreSQL в Docker Compose. Первый запуск
выполняет `./deploy/deploy.sh` после создания `.env.production`, обновление —
`./deploy/update.sh`, резервную копию — `./deploy/backup.sh`, откат —
`./deploy/rollback.sh`. Порядок действий описан в разделах 19 и 20
документации.
